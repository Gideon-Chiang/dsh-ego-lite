## 1. 逐条修复与证据

每条都按 BUG-STANDARD §7 的模板：oracle → 复现 → 根因 → 修法 → 验证。全部在 **spawn 之前**拒绝（"Nothing ran" 仍成立），除硬性行为外无新增 spawn。

### 1.1 [S3] 行注释只认 `\n` 行尾（L1 ECMAScript + L4 与 V8 差分）
- 复现（修前）：`js{expression:"// c\u000d1"}` → `js: expression is required …`（应为 `1`）；U+2028/U+2029 同。
- 根因：`saysNothing()` 用 `indexOf("\n")` 找行注释结尾；ECMAScript 的 LineTerminator 是 LF/CR/U+2028/U+2029。
- 修法：新增 `isLineTerminator()` / `skipLineComment()`（仍是 O(n) 单次前进，无回溯）。
- 验证：`{expression:"// c\u000d1"}` → `value:1`；`"// c\u20281"` → 1；`"// c\u000d\u000a1"`/`"// c\u000a1"` 不变；`"// c\u000d"`（纯注释）仍拒绝。测试：**P14**。

### 1.2 [S3] 函数值 marker 可被伪造（L3-1/L3-8 静默丢值）
- 复现（修前）：`js{expression:"({__dshFunctionValue:true, secret:42})"}` → `{ok:true, value:null, valueType:"function"}`，`secret` 消失。
- 根因：宿主只比对 `=== true`，页面数据/调用方表达式命中该键即被当成"不可承载的函数值"。
- 修法：每次调用生成 `randomBytes(8)` token，写进 probe 的 marker 与宿主比对；token 在源码之后生成，源码无法猜到。
- 验证：同一输入现在返回完整对象且无 `valueType`；`() => 1`（mode:expression）、`async () => () => 1`、`Promise.resolve(() => 1)` 仍正确标记。测试：**P15**。

### 1.3 [S3] `fn:` 静默覆盖 `mode:`（L3-5）
- 复现（修前）：`{fn:"(x)=>x", arg:2, mode:"expression"}` → `2`，`mode` 被无声忽略。
- 修法：`fn:` + 非 `function` 的显式 `mode` → 报错（`mode:"function"` 或缺省才允许）。
- 验证：上述调用报错且零 spawn；`{fn:"(x)=>x*3", arg:4, mode:"function"}` → 12。测试：**P16（含零 spawn 断言）**。

### 1.4 [S3] `arg` 在 statements/expression 下被静默丢弃（L3-5）
- 复现（修前）：`{expression:"return 1", mode:"statements", arg:9}` → `1`；`{expression:"(x)=>x", mode:"expression", arg:2}` → 函数值标记，`arg` 无痕消失。
- 修法：这两种模式下传 `arg` 直接拒绝并给出替代路径；auto + 函数源码仍允许（schema 已写明 `arg` 的生效条件）。
- 验证：两条均报错且零 spawn；`{expression:"(x)=>x*3", arg:4}`（auto）→ 12。测试：**P16**。

### 1.5 [S4] `wait` 空源两套文案（L3-6）
- 复现（修前）：`wait{for:"function", expression:";"}` → `expression is required for for="function".`，而 `"; ;"`/`"// c"`/`"/*c*/;"` → `… not a single expression (nothing ran).`
- 修法：wait 侧判空改用 `saysNothing()`；顺带删掉不可达的 `?? "true"` 默认值。
- 验证：五类输入统一文案、零 spawn。测试：**P17**。

### 1.6 [S3] 不生效的参数被接受后静默忽略（L3-5，7 个工具）
新增 `unusedParameters()`：显式传入、但该调用不可能读取的参数一律报错（靶向句柄 `name`/`page`/`id` 与该 action 真正使用的 `timeoutMs` 除外）。

| 工具 | 修复前（静默忽略 / 静默默认） | 现在 |
|---|---|---|
| `ego_app_key` | 缺 `key` 时**按 Enter**；`selector`（非 press）、`html`（非 paste）、`text`（press/down/up）被忽略 | 缺 `key` 报错；错配参数报错；`type`/`insert_text` 缺 `text` 报错 |

### 1.7 [S3] `finish` 的 `keepPages: []` 语义反了（L3-5）
- 复现（修前）：`{action:"finish", keepPages: []}` 被当成"没传" → `keep:"all"`（**保留全部**，与"一页不留"相反）。
- 修法：`keepPages` 一旦是数组就按显式值下发；`[]` 即 `keep:[]`。同时传 `keep` 与 `keepPages` 报错。
- 验证：P20（冲突零 spawn；`keepPages:[]` → `ok:true`，实测 receipt `closedManagedLabels:["p1","p2","p3","p4"]`）。

### 1.8–1.10 [S3/S4] 独立审查发现的三条（同轮修掉）
由独立审查员（xiaomi/mimo-v2.6-flash，max）对 0.1.16 diff 做只读复核时发现，均按同一标准修复：

- **[S3] `fn:` 与 `expression:` 同时给 → expression 静默蒸发（L3-5）**：`{fn:"(arg)=>arg.n", expression:"999", arg:{n:7}}` 以前 `ok:true, value:7`，生成的脚本里根本没有 `999`。修法：两者同时给且 expression 不是纯注释 → 报错。验证：P21（零 spawn）；`expression:"/* nothing */"` 仍允许。
- **[S3] `auto` + `arg` + 语句体 → arg 静默蒸发（L3-5）**：`{expression:"const x = 1; return x;", arg:{k:1}}` 以前 `value:1` 且 `page.evaluate` 只传一个实参。根因是此前的拒绝条件只覆盖显式 `mode:"statements"`，没覆盖 auto 回落。修法：按 `effectiveMode` 判定。验证：P22（零 spawn）；auto + 单表达式 + arg 仍返回 12。
- **[S4] dialog `waitMs` 的 30 s 截断不可见（L3-5 / L2）**：`waitMs:60000` 实际只等 30 s，结果无任何提示。修法：结果回显 `waitMs:{requested,applied,clamped}`（与 `wait_control` 同口径），schema 写明 cap。验证：P23。

### 1.11–1.12 [S3/S4] 第二轮审查发现（同轮修掉）

- **[S3] `ego_app_select` 的 `index` 静默覆盖 `label`/`value`（L3-5）**：`{selector:"#s", index:0, label:"Foo"}` 以前按位置选中，`label` 无提示蒸发；schema 只文档化过 "label wins over value"，从未声明 `index` 的优先级。修法：`index` 与 `label`/`value` 同传即报错；`label` 覆盖 `value` 保持不变。验证：P24（含 `label`+`value` 仍可用的对照、零 spawn）。
- **[S4] `wait_event` 非法 `event` 先报 `saveAs` 参数错（L3-6）**：`{action:"wait_event", event:"bogus", saveAs:"…"}` 会得到 "saveAs cannot be used…"，把所有排查方向都带偏。修法：先按事件名校验（popup/download），再进参数白名单。验证：P25。
