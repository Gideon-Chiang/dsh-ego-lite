## 缺陷：ego lite 未完成 onboarding 时静默成功

ego 应用首次运行时 onboarding 未完成，`ego-browser` CLI 的实际输出是：

```
Please complete the onboarding process first. A setup window has opened; follow
the on-screen instructions to continue. After completing onboarding, open a new
terminal window for the command to take effect.
```

但 `ego_app_status` 返回：

```json
{ "ok": true, "executable": "C:\\Program Files\\Citro Labs\\ego lite\\Application\\0.6.2.5\\ego-browser.exe", "data": null }
```

即：**CLI 的提示被吞掉，`ok: true` + `data: null`**。agent 看到的是"调用成功但没数据"，
只能靠猜；应识别这类 CLI 输出并返回 `ok: false` + 原文提示 + hint（"请先在 ego lite 里完成 onboarding"）。
同理建议给所有 `data === null` 且 CLI 有非哨兵输出的情况加兜底错误。

## 缺陷 1（重要）：`takeover` 假成功

```
ego_app_space {action:"takeover", name:"工具补测"}  →  {"ok":true,"spaceId":2,"tookOver":true}
ego_app_navigate …                                  →  ❌ 仍报 "Control … is with the user … paused"
ego_app_status                                      →  space 2 ownership = "agentDelegatedToUser"
```

根因在 `lib/index.js:386`：

```js
body: `await ego.takeOverTaskSpace();`,          // ← 没有传 spaceId
result: `{ spaceId: task.spaceId, tookOver: true }`  // ← 无论成败都报 true
```

官方语义是 `const task = await takeOverTaskSpace(spaceId)`（ego 自己的错误提示里就写着这句）。
用 `ego_app_run` 执行 `await takeOverTaskSpace(2)` 之后，ownership 立即变成 `agent`，
下一条 `ego_app_navigate` 恢复正常 —— 证明就是这一处没传 id。

建议改为：

```js
const t2 = await takeOverTaskSpace(task.spaceId);
if (!t2 || t2.ownership !== 'agent') throw new Error('takeover did not return control to the agent (ownership=' + (t2 && t2.ownership) + ')');
```

## 缺陷 2：`ego_app_run` 文档写错（`taskSpace()` 是 Promise）

README/工具描述里的示例 `taskSpace(name|id)` 不 await，照抄会直接失败：

```
TypeError: task.page is not a function
```

实测必须 `const task = await taskSpace('名字')` 之后才有 `page/pages/tabs/handOff/waitForControl/finish/cdp/adopt/release/newPage`。
建议在工具描述和 README 里把 `await` 写全。

## 次要问题

1. `ego_app_gesture` 的 highlight 返回 `"3 mouse highlight shown."` —— 把 spaceId 插进了人话里，读起来像"3 个高亮"。
2. `ego_app_space{action:"delete"}` 的报错分支：
   - 空间已关闭时返回 `nothing matched: pass ids, or the name of a finished space`（应说明"该空间已不存在"）；
   - 删除成功时返回的 `spaces` 数组是**删除前的快照**（仍列出刚删掉的空间），容易误判。
3. `close` 动作可用，但工具的 action 枚举描述里没列它（README 里有）。
4. `ego_app_pointer{action:"drag"}` 走的是原生 HTML5 拖放：对**没有 draggable 的元素**（如普通 div）
   拖拽会 `ok:true` 但什么都不发生（本次首轮实测 drag 计数=0 即此原因；把源元素改成 `draggable=true`
   后 dragstart/drop 均正常、`dropText="dropped: dragged"`）。建议文档标注该限制。

## 复验中额外发现（已写进 README 语义边界 14/15）

1. **`receipt.dialog` 在 0.6.2.5 是普通对象**（`{url,frameId,message,type,hasBrowserHandler,defaultPrompt}`），不是方法；
   最初按方法读会拿到 `type:null`，已兼容两种形态。
2. **未应答的对话框会跨调用残留**：点击触发 alert 后若不 `acceptDialog()`，该页后续每一轮都报
   `PageDialogOpenedError`（guide 说"跨轮自动关闭"，实测不成立）。测试矩阵因此被连锁卡住过一次。
3. `page.click(sel, { button: "right" })` 可用；`page.mouse.click()` 只吃坐标。
