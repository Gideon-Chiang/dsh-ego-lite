## 0.1.15 改了什么（本轮重点）

用户重构：删除手写词法扫描器 → **parser oracle（`new Function` 只编译）+ value probe（求值，仅当结果是函数才调用）**。Lead 在重构之上修：

1. **尾分号**：`trimSource`（trim + 去尾分号，不是词法分析）——`1+1;`→2、`() => 1;`→1、`fn:"(x)=>x+1;"`+arg→42、`wait{expression:"() => 1;"}` 可执行。
2. **空源码**：`ego_app_js{}` / `{expression:""}` → `expression is required`（以前静默 `evaluate(() => undefined)`）。
3. **函数值不再静默丢**：`mode:"expression"`（绝不调用）、`mode:"function"`（返回值）、`mode:"statements"`（体内 return）与 auto 的 probe 统一标记 `{ value:null, valueType:"function", note }`。
4. **双包装 oracle**：同一源码须同时通过 `(src)` 与 `[src]`，`1); evil(); (2` 这类语句逃逸在 spawn 前可读拒绝（"Nothing ran" 承诺成立）。
5. `statements` 体包内层箭头以检测函数返回值。

## 6. 已知残余 / 限制

- **(A) 文本包装逃逸（理论）**：双包装 oracle 挡住"关闭一种括号再写语句"的逃逸；刻意构造同时满足两种包装的源码仍可能绕过——源码由调用方/模型提供，能力等价于 `ego_app_run`，彻底消除需引入 JS parser 依赖（不引入）。
- **(B) auto 调用函数值**：生成器函数被调用返回 truthy 迭代器（wait 立即满足）；`class A {}` 被调用抛 `Class constructor cannot be invoked without 'new'`。要"只取值不调用"用 `mode:"expression"`。`wait{for:'function'}` 的谓词每次轮询都会求值（是函数则调用），有副作用/依赖 this 的函数不要当谓词；谓词抛错会中止等待。
- **(C) 既有 S3**：结构化 `log` 上限 16000（`logLength` 为 UTF-16 字符数）、非字符串 label 原样进结果、`id:0` 是真实空间、`release` 的回读受 ego 先抛限制、上游/环境项（adopt 成功路径需用户页、真 app 同名空间不可构造、status 面板高亮不可观测、8 页预算、串行约束）。
- **(D) 措辞（非缺陷）**：auto 模式下 `1); evil(); (2` 的拒绝文案是「the statements source is not valid JavaScript」——因为 auto 先判"非表达式"再落 statements；语义正确、零 spawn，只是措辞可更直接。`wait` 侧对**注释型空源**（`; // c`、`/*c*/;`）报「not a single expression」而不是 `expression is required`（js 侧已统一）；同样零 spawn、可读。
