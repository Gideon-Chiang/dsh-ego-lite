# 缺陷判定与修复标准（Bug Triage Standard）

> 适用范围：`dsh-ego-lite` 的全部缺陷判定、严重度定级、修复与发布决定。
> 本文件是**唯一标准**。任何"这是不是 bug / 该不该修"的争议，先回到本文件；本文件没覆盖的，先补标准再判定（补标准要评审，不能临场发明）。
> 维护：新增/修改规则必须单独提交并说明动机，不得为了让某个具体结论成立而改规则。

## 0. 一句话定义

**Bug = 一个失败的 oracle。**

不是"作者觉得不对"，也不是"违规了作者的自我描述"。判定一个现象是不是 bug，只问两件事：

1. 存在一个**独立于作者意图**的判定器（oracle），能稳定地判"失败"吗？
2. 这个失败**可复现**吗（同一输入 → 同一结论，别人也能跑出来）？

两个都是"是" → 是 bug。任何一条是"否" → 不是缺陷（最多是偏好、风险或待定语义）。

**判定与处置必须分开报告**：`bug: yes/no` 与 `fix: now/next/won't fix` 是两个独立字段。"已知限制"**只能**改变处置，不能改变 bug 判定——把缺陷写成"已知限制"不等于它不是缺陷。

## 1. Oracle 分层（客观性从强到弱）

| 层 | 锚点 | 说明 | 可接受的证据形态 |
|---|---|---|---|
| **L1** | 外部规范 | ECMAScript、JSON (RFC 8259)、SemVer 2.0、Playwright/ego CLI 公开 API、CWE 弱点目录 | 规范条款 + 引用 |
| **L2** | 先于发现冻结的公共契约 | 本仓库 README / 工具 schema 描述 / CHANGELOG / 已发布的测试 | 冻结版本号 + 原文 |
| **L3** | 不变量 / 性质 | 见 §2 的项目不变量清单；可用 property 测试机器验证 | 实测数据（规模、键集、spawn 计数） |
| **L4** | 差分 oracle | 与 V8 / 真 ego app / 上一版本对比：两个独立实现给出的结论不一致 | 对照表 |
| **L5** | 危害类别 | hang / crash / 静默错值 / 数据丢失 / 响亮报错 / 文案 | 可观测行为 + 严重度 |
| **L6** | 作者意图 / 最少惊讶 | **不作为判定依据**，只能用于提出改进建议 | — |

L2 的时效性规则：**契约必须先于发现存在**。同一发布里、在发现问题之后补写的"已知限制"，只能作为"处置决定（won't fix）"，**不能**作为"不是 bug"的证据——那是循环论证。

## 2. 项目不变量（L3 契约，违反即缺陷）

1. **ok:true 可信**：报告成功的结果不得丢值、丢键或不说明语义；失败不得被报告成成功。
2. **ok:false 可信**：失败必须带可读错误（+ 可行的 hint），不得把未验证的状态报告成已完成。
3. **"Nothing ran" 可信**：被输入门禁拒绝的调用必须零 spawn。
4. **不钉死宿主**：任何调用方输入都不得让 `tool.execute` 同步阻塞或病态变慢（禁止指数回溯；长输入的耗时须随长度线性或近线性增长）。
5. **显式输入不得静默蒸发**：调用方明确传入的参数，要么在该调用上生效，要么被明确拒绝；不得"接受但绝不生效且不提示"。
   - 例外（不适用本条的参数）：靶向句柄 `name` / `page` / `id`，以及该 action **确实读取**的预算 `timeoutMs`。给一个不读取预算的 action 传 `timeoutMs`（如 `ego_app_page{action:"fetch"}`）仍算违反本条。
   - 前置校验不算"生效"：DSH 工具框架会按 schema 先校验类型（`type:"number"` 传字符串直接抛 `ToolArgsError`），所以被框架拒绝的输入永远到不了 `execute`。判定时以**到达 execute 之后**的行为为准。
6. **等价输入等价诊断**：同一类"无内容/非法"输入不得给出两套互不兼容的错误文案（除非有可解释的理由）。
7. **规范一致**：JS 语义以 ECMAScript 为准；对外 JSON 以 RFC 8259 为准；版本语义以 SemVer 2.0 为准。
8. **可序列化**：成功结果中的错误/函数/thenable 等不可 JSON 承载的值必须有明确标记，不得静默变形。
9. **单位与命名固定**：公开字段的单位一旦写进文档（如 `logLength` 为 UTF-16 字符数）即视为契约，改动需按 SemVer 处理。

## 3. 判定流程（每条现象都走这 6 问）

1. **能否写成一句可证伪的期望？**（"输入 X 不应阻塞超过 1 s"）不能 → 不是缺陷，是建议。
2. **依据落在 L1–L5 哪一层？** 只落在 L6 → 不是缺陷。
3. **有独立 oracle 吗？** 规范条款 / 差分 / 性质测试 / 可观测危害，至少一个。
4. **最小复现多大、触发概率多高？**（记录字符数、构造条件）
5. **危害类别是什么？** 用于定级（§4）。
6. **处置理由是哪一种？** "无失败 oracle"（→ not a bug）还是"已判定为缺陷但选择不修"（→ won't fix + 理由 + 复现方式）。两者不得混写。

## 4. 严重度与处置

| 级别 | 判据（可观测危害） | 默认处置 |
|---|---|---|
| **S1** | 数据丢失/错误执行/安全边界失守/**宿主不可恢复**（需 kill 进程） | 阻断发布，必修 |
| **S2** | 主要功能不可用、同步阻塞、超时机制失效、静默错误结果 | 阻断发布，必修 |
| **S3** | 边缘输入的错/漏、静默忽略、规范级不一致、文档与实现矛盾（有替代路径） | 必修（默认）；确需推迟必须记录 won't-fix 理由 |
| **S4** | 文案、一致性、可读性，无可观测错误 | 顺手修；不阻断发布 |

**优先级 = 严重度 × 可达性 × 检测难度。** 可达性指"调用方/模型在正常使用中踩到的概率"，要给出构造条件；检测难度指"用户能否自己发现"（静默者更危险）。

**外部因素**：ego app / Playwright / 上游 CLI 的行为差异记为 `upstream`，不算本项目 bug，但必须在文档登记。

## 5. 修复纪律

- **默认直接修**：判定为 bug 即修，改完跑测试、报实测结果；不为每条 bug 单独征求同意。
- **必须问用户**的唯一情形：两种语义取舍都自洽且**会改变对外契约**（例如"报错"vs"静默兼容"、"破坏性 API 变更"），以及不可逆操作（发布、改版本号之外的推送、删数据）。
- **最小修复**：修根因，不夹带重构；行为变化必须写进 CHANGELOG。
- **回归测试**：能在本地复现的 bug，修复必须附回归用例（优先存在既有测试文件里）。
- **验证边界**：假 CLI 证明不了真 app 的运行期契约（如 Playwright 对 async 回调的支持），这类必须标注为"未覆盖"并说明原因，不得用 mock 冒充全量验证。
- **记录**：每条修掉的 bug 在 CHANGELOG 里写"症状 → 根因 → 修法 → 验证"，并注明 oracle 层级（L1–L5）。
