# dsh-ego-lite

Drive the **installed ego lite app** from DeepSeek Harness with 20 structured `ego_app_*` tools. Every call runs through the official `ego-browser` CLI and lands inside a real ego TaskSpace — visible in the app's Space panel, using the app's own profile and logins.

- No second Chromium, no CDP port, no browser extension
- Coexists with the official `ego-browser` skill (same IPC channel)
- Tool-level validation, readable errors, and explicit handling of ego's behavioural edges

## Install

Published on npm as [dsh-ego-lite](https://www.npmjs.com/package/dsh-ego-lite).

```powershell
# as a DSH plugin, from npm (recommended)
dsh plugin --profile web add dsh-ego-lite

# as a regular npm dependency in your own project
npm install dsh-ego-lite

# straight from GitHub
dsh plugin --profile web add github:Gideon-Chiang/dsh-ego-lite

# local development
dsh plugin --profile web add file:C:/path/to/dsh-ego-lite
```

Restart dsh afterwards (plugins are not hot-reloaded; the profile copy is a physical copy, so re-copy and restart after editing sources).

> `dsh plugin` installs the package into the selected profile. If you only want it as a Node dependency, use `npm install dsh-ego-lite`; at runtime `@deepseek-ai/dsh-tools` is supplied by the DSH host (optional peer) and does not need to be installed separately.

## Requirements

- ego lite installed and onboarded, and running
- DSH able to execute commands on the same machine (`danger-full-access` recommended)

The CLI is auto-detected under `C:\Program Files\Citro Labs\ego lite\Application\<version>\ego-browser.exe`; override with the `executable` config or `EGO_BROWSER_CLI`.

## Behaviour changes in 0.1.15

0.1.15 deletes the hand-written lexical scanner and replaces it with **the engine's own parser as the oracle plus a value probe**; the previous release's classification edges (comments, regex literals, generators, nested default parameters) are gone at the root.

1. **`ego_app_js` / `wait{for:'function'}` no longer guess "function source vs expression"**: `parsesAsExpression()` only compiles (never runs), and the same source must compile under **both** `(src)` and `[src]` (two-wrapper oracle: a statement escape that closes one bracket leaves the other unbalanced); `valueProbe()` evaluates the source and calls it **only when the value really is a function** (decided after `await`). So `wait{for:'function', expression:"(x = 1) => x > 5"}` really times out instead of passing on the first poll because the arrow itself is truthy.
2. **`js` `auto` semantics**: a single valid expression is evaluated; when the value is a function it is **called** (`() => 1+1` → 2, `() => ({a:1})` → the object). Use explicit `mode:"expression"` to get a value **without** calling: it never invokes the source and reports `{ value: null, valueType: "function", note: … }` when the result is a function (previously it vanished silently).
3. **No path silently drops a function value (async included)**: `mode:"expression"`, `mode:"function"` (function returned), `mode:"statements"` (body returns a function) and auto decide **after `await`**, so `async () => () => 1`, `() => Promise.resolve(() => 1)`, `Promise.resolve(() => 1)` and `(async () => () => 1)()` are reported too (`valueType:"function"`). A side effect: a `mode:"statements"` body now supports top-level `await` (previously a syntax error) and every mode awaits/flattens Promises.
4. **A trailing semicolon is part of the value**: `{expression:"1+1;"}` → 2, `{expression:"() => 1;"}` → 1, `fn:"(x)=>x+1;"` + `arg` works (trim only, not a lexer).
5. **An empty source is refused (the guard is a linear scan)**: `ego_app_js{}`, `{expression:""}` and sources that contain only whitespace/semicolons/comments (`;`, `;;`, `; ;`, `; // c`, `/*c*/;`) → `expression is required`; `wait{expression:";"}` likewise reports `expression is required for for="function"` (previously it silently evaluated to `undefined`).
6. **Wrapper escapes are refused before spawning**: the same source must compile both as `(src)` and as `[src]` (two-wrapper oracle), so `js{expression:"1); evil(); (2"}` is rejected readably with **zero spawns** — "Nothing ran" holds.
7. **Known limitations (declared, not pending bugs)**:
   - (A) A deliberately crafted source that satisfies both wrappers could still slip through in theory; the source is caller/model supplied and equivalent to `ego_app_run`, and closing it fully would need a JS parser dependency (not added).
   - (B) `js` `auto` **calls** function values: a generator call returns a truthy iterator (wait satisfies immediately) and `class A {}` throws `Class constructor cannot be invoked without 'new'`. Use `mode:"expression"` to only read the value. A `wait{for:'function'}` predicate is likewise evaluated and (when it is a function) called on **every poll**; do not use side-effecting functions as predicates, and a throwing predicate aborts the wait.
   - (C) Other pre-existing S3 items: structured `log` cap of 16000 (`logLength` counts UTF-16 code units), non-string labels pass through result fields, `id:0` is a real space, and the upstream/environment limits (adopt success path needs a user page, same-name spaces cannot be built on the real app, the status panel highlight is not observable, the 8-page budget per space, real-browser suites must run serially).

## Behaviour changes in 0.1.14

0.1.14 closes the last two N4 lexical edges left by 0.1.13 (N4-a/N4-b); everything else is unchanged.

1. **N4-a skips comments**: the `isBareFunctionSource` scanner now skips `//` line comments and `/* … */` block comments, so `}` / `)` / quotes inside comments no longer break function-source detection. `(x) => { // note
 return x; }`, `(x) => { /* } */ return x; }` and `(x) => x /* ) */ > 0` are now function sources; previously they were classified as expressions, wrapped as a truthy arrow, and made `wait{for:'function'}` **pass on its first poll**. **Comments count as whitespace in the scanner**: they are skipped without changing lexical state, so `return /*c*/ /}/.test(x)`, `(a = /*c*/ /[)]/…) => a` and `(a) => a + /*c*/ /[)]/` are function sources too; **header comments** (`function /*c*/ f(){}`, `async /*c*/ () => 1`, `function* /*c*/ g(){}`) work as well; **comments are also allowed between `function` and the generator `*`** (`function /*c*/ * g() {}` and `async /*c*/ function /*c*/ * g() {}` are function sources). **Generator note**: `function*` is correctly recognised as a function source, but using it as a `wait{for:'function'}` predicate passes immediately because calling it returns a truthy iterator object — that is JavaScript semantics, not a classification false pass; use a non-generator function (e.g. `function /*c*/ () { return false; }`) when you need a boolean predicate.
2. **N4-b regex after keywords**: a `/…/` following `return`/`typeof`/`instanceof`/`case`/`yield`/`await`/`delete`/`void`/`in`/`of`/`new`/`do`/`else`/`throw` is treated as a regex and skipped (`(x) => { return /}/.test(x); }` and `(x) => typeof /}/.test(x)` are now function sources).
3. **Unchanged**: call expressions `(async()=>1)()`, `(0,()=>7)()`, `function(){}()`, `((a)=>a)` are still expressions; `//` and brackets inside strings/templates are unaffected (`skipQuoted` runs first); division `a / 2`, `a++ / 2`, `a && /x/.test(a)` still work; `new Function("return (src);")` remains the final gate. Very narrow edges remain (they do not affect this round's goal): regex in statement position after `)`/`}` (`if (x) /}/…`), a trailing `//` at EOF without a newline (the js path gives a readable error), `async => 1`. Note: `(a /* ) */) => a` is now **true** (comments count as whitespace) and is not a residual.

## Behaviour changes in 0.1.13

0.1.13 closes the five S3 follow-ups recorded by the 0.1.12 audit (N4/N6/N7/N9/N2①).

1. **`isFunctionSource` now matches brackets (N4)**: arrows with nested parentheses in their parameters (`(x = foo()) => x > 0`, `(a = (1)) => a`) are now correctly recognised as function sources; previously `wait{for:'function'}` wrapped them as `() => (…)`, so the arrow itself was truthy and the wait passed on its first poll (a false pass) — that is gone. Since 0.1.13 these four are **all treated as expressions** (the whole source must be exactly one function expression): `(async () => 1)()`, `(0, () => 7)()`, `function(){}()`, `((a) => a)` — **`function(){}()` was treated as a function source in 0.1.12**, while the other three were already expressions there (do not write "false in both versions"). Plain expressions such as `document.title` are expressions too. **Parentheses inside regex literals are not misparsed either**: in sources like `(x) => /\)/.test(x)`, a `/` is recognised as a regex and `[...]` classes and escapes are skipped, so bracket matching stays correct.
2. **Poll wording derives from the constant (N6)**: 11 `~2400 ms` error messages are now interpolated plugin-side from `~${SPACE_WATCH_TIMEOUT_MS} ms` (the generated script still contains the literal `~2400 ms`; user-facing text is unchanged); changing the constant updates the wording automatically, with no runtime concatenation.
3. **Page `label` no longer has to be a string (N7)**: `pagePrelude` only requires the Page to have a `label` (non-string labels work); a missing/`null` label still fails readably — a normal Page is no longer failed just because its label is not a string. A non-string label **flows into result fields unchanged** (e.g. `page: page.label`), so consumers must not assume it is a string.
4. **Structured success `log` is capped (N9)**: on structured success, `log` is capped at **16000 characters**; beyond that it is truncated and carries `logTruncated:true` + `logLength:<original length>`; the shape is unchanged below the cap. **The two flags differ**: `logTruncated` means the structured `log` was cut at 16000 characters, while `truncated` means the raw CLI output was cut by `maxOutputBytes`; `logLength` is the **UTF-16 `.length` (character count)**, not bytes. `ego_app_run` still returns the full log (contract unchanged).
5. **`ego_app_space` `id` now wins over name (N2①, behaviour change)**: consistent with Page tools and `ego_app_tabs{scope:'space'}` — **when both `name` and `id` are given, `id` is used** (matching what the schema always said). **`id:0` hits the user's default space** (id 0 is a real space, not a placeholder/note value) — an existing call that passed `id:0` as a note will really target the user space after upgrading; pass only `name` to address by name.

## Behaviour changes in 0.1.11

0.1.11 closes round 3: it clears the remaining S3 items, brings the 0.1.10 fail-closed theme to `ego_app_tabs` / `ego_app_status`, and lets generated scripts be unit-tested without the real app.

1. **The log no longer swallows page output (A)**: `log` drops only this run's *actual* result line — a token run drops only lines starting with `@@DSH_RESULT@@<token>`; `ego_app_run` (plain) drops only the exact selected result line. A bare `@@DSH_RESULT@@...` line printed by the page stays visible. Parse order is unchanged (sentinel → onboarding → exit code → plain text → truncation).
2. **Read-failure hardening (B/H)**: new `describeRead()` (try/catch, 300-char cap, `"(unprintable)"` fallback). `ego_app_status` now always returns `{version, versionError, profiles, profilesError, tabs, tabsError, tabsSpaceId, spaces}` — `version`/`profiles` failures become `versionError`/`profilesError` instead of error objects passed off as data; when `tabs` cannot be read, status selects the newest agent space once and retries (a brief selection, no other side effects), recording it in `tabsSpaceId` (only on a successful re-read after selecting — never together with `tabsError`); only a second failure yields `tabsError`.
3. **Function-source detection and parse-before-spawn (C/T/N-a)**: new exported `isFunctionSource()` (parses with `new Function`, never runs the body). `wait{for:'function'}` inlines a whole function source as `(${expr})`, otherwise keeps `() => (${expr})`; `ego_app_js`'s `fn` implies function mode and `mode:'auto'` treats a function-source expression as function, while explicit `expression|statements` never auto-switch. Both drop **trailing semicolons** before classifying/wrapping (`() => 1;` works; a statements body keeps its text as-is; `1+1;`'s auto classification only becomes correct with 0.1.12 R6), and both parse the source **before spawn**: syntax errors fail readably (`needs a valid function source or expression` / `… is not valid JavaScript`) with zero side effects. This also fixes `ego_app_js{expression:"() => 1+1"}` returning a function and silently dropping `value` (now returns `2`).
4. **Terminal/handoff actions capture values first (D)**: `page{action:'close'}` captures `page.label` before closing; `close`/`finish`/`complete`/`mark_error`/`handoff`/`takeover`/`wait_control` capture `task.spaceId` at script start — results keep id/label even if the action invalidates them. The literal `task.spaceId` inside user data is never rewritten.
5. **`create` without a space id (F)**: errors with `createTaskSpace() did not return a space id: …; no space was selected` instead of calling `useTaskSpace(undefined)`.
6. **`dialog` behaviour (G/N)**: `waitMs` negative/NaN → `0`, capped at `30000`, and `waitForTimeout` is wrapped in try/catch so an opened dialog is always answered (no more "left-open alert blocks the page for ~15 s"); `promptText:""` is now really sent (only an absent value means "no text"); the result carries the trigger `receipt`, and `handled:false` carries a `note` confirming there was no dialog to answer. If the trigger click itself throws, the dialog is **still answered first**, then the click error is re-thrown with `any dialog it raised was still answered (handled=…)` — no dialog is left open.
7. **`ego_app_tabs` and space-list evidence (I/J/K/L/M/U/N-c/N-d/N-e)**: `scope:'space'` results carry `targetId`/`openedBy`; `scope:'space',action:'open'` carries `opened`; `scope:'app',action:'open'` carries `created` (the readable `createTab()` result) and `verified:boolean|null` (whether the tab list actually grew — evidence only, never a failure on `false`, to avoid list-refresh races; `null` when the pre-read failed, and 0.1.12 keeps creating the tab) — note **an app-level open also adds a managed Page to the current space and consumes ego's 8-page-per-space budget**. `open_page` fails when no Page with a label comes back; `pages`/`tabs`/`adopt`/`release` fail readably when `task.pages()`/`task.tabs()` is not an array (`the TaskSpace page/tab list is unreadable`); `adopt` re-reads `task.pages()` and returns `verified:boolean`; `user_page` works with both sync and async `task.userPage()`; `ego_app_tabs` treats a blank `name` as omitted.
8. **`ego_app_page{action:'fetch'}` (O)**: `options.saveAs` is echoed as `saveAs` — the tool/parameter descriptions now say "ego writes the file; the path is echoed back but not verified"; this call does **not** verify the file exists.
9. **`ego_app_gesture` (P)**: `shown:null` when the API returns nothing (previously `undefined` still reported true); `detail` is capped at 500.
10. **`describeReceipt` (Q)**: page-controlled dialog strings such as `message`/`defaultPrompt` are capped at 2000 and marked `…[truncated N chars]`.
11. **`ego_app_run` `truncated` (R)**: when the result line is complete but the output tail was truncated, the result now carries `truncated:true`; the exit-code-first diagnosis order is unchanged.
12. **New hints (S)**: a dedicated tab-read hint (`would not list its tabs…`, no longer pointing at the TaskSpace list), plus adopt/release and the "Page budget reached" (8 pages) hints.
13. **Unclosed quotes stay plain CSS (conservative)**: `[data-x="a>>b]` is not guessed to be an ego locator; it stays plain CSS for `querySelector` and is locked by tests.
14. **Real-browser live suites must run serially**: ego's "currently selected space/page" is application-global state; concurrent runs from two sessions/processes interleave pages (observed once as a false red in the 0.1.9 round). Run `npm run test:live` serially in one session.

## Behaviour changes in 0.1.10

0.1.10 closes out 0.1.9: it separates "the state could not be read" from "the state was read but not verified", and finishes the audit residuals.

- **Fail-closed reads**: `ego_app_space{action:'list'}`, `ego_app_status`, `delete`, space-action resolution and the six polled post-checks now **fail** when `taskSpaces` cannot be read (the error contains `unreadable`; the hint says run `list`/`ego_app_status` and retry) — a broken read is never "no spaces / deleted / empty list". `ego_app_status` degrades a failed tab read (anything that is not a list) to `tabs: []` + `tabsError`. **Two classes, by design**: the list refresh after `create`/`use`/`claim` is **best-effort** — a read failure only adds `spacesError` and the call still returns `ok:true` (the action's own evidence, e.g. `spaceId`, is already there); while `list`/`ego_app_status`/`delete`/space-action resolution and the six post-checks **must** fail closed. Do not read this as "any read failure is an error".
- **Task-ended fallback parity**: recovered results now carry what the normal path would: `takeover` → `name` when it was addressed by name, `wait_control` → `requestedTimeoutMs`/`timeoutMs`/`clamped`/`value`, `finish` → `keep` (the requested value). A `finish(keep:true)` recovery note states that page-level retention cannot be verified from the space list — use the normal-path receipt when `keptManagedLabels` matters.
- **`timeoutMs` hygiene**: explicit `<= 0` / non-finite values are rejected before any side effect with `timeoutMs must be a positive number of milliseconds (it is a duration, not a flag).`; `ego_app_page{action:'reload'|'focus'}` now forwards `timeoutMs` (`close` takes none).
- **Locator quotes**: `>>` / `:has-text(` inside quoted CSS strings (`[data-x="a>>b"]`) is literal CSS, not an ego locator; markers outside quotes still go to ego's locator parser.
- **`ego_app_js` `mode`**: `auto | expression | statements | function` (default `auto` keeps the punctuation heuristic; `fn` implies `function`). `ego_app_wait{for:'function'}` accepts a whole function source instead of wrapping it in `() => (...)`, which made the wait pass immediately.
- **`pageCreated`**: **actual Page tools** (`navigate`/`snapshot`/`screenshot`/`click`/`fill`/`key`/`pointer`/`select`/`wait`/`js`/`cdp`/`dialog`/`upload`/`download`/`page`) now include `pageCreated` (`true` when a silent `newPage()` created the page); `ego_app_space{action:'open'}` and `ego_app_gesture` do **not** return it (matching 0.1.9); `open` also no longer creates a Page by itself (`usePage:false`) — a new space's `pages` may be empty and the first Page-tool call does the `newPage()`.
- **abort**: a caller AbortSignal kills the child process and returns `aborted by the caller` immediately instead of waiting for the plugin's 180 s timeout.
- **Sentinel nonce**: plugin-generated scripts use a per-run random suffix, so page text faking a whole `@@DSH_RESULT@@…` line can no longer spoof structured results. The nonce only replaces the plugin's own printed expression: **a user script containing the same literal (including `@@DSH_NONCE_SLOT@@`) is never rewritten**, and `ego_app_run` keeps the plain `@@DSH_RESULT@@` contract. A structured call that cannot find this run's token line gets a dedicated "no result line carrying this run's sentinel token" failure instead of the old "script never ran" message.
- **Rendered truncation marker**: results over 20000 characters now end with `…[renderedTruncated omittedChars=N limitChars=20000]` instead of being silently cut. **20000 is this plugin's own constant** (`OUT.render`'s limit), not a host budget — it is our choice.
- **New hints**: `no space with id`, `only removes user-owned`, `matches N spaces`, `could not be read|could not be verified`.

## Behaviour changes in 0.1.9

- **Post-transition `ok:false`**: `close`/`finish`/`complete`/`mark_error`/`handoff`/`wait_control` now poll the space list (every 150 ms until the 2400 ms deadline; measured 17 polls / ~2.6 s) and report the *measured* `ownership`. An action can land and still return `ok:false` (e.g. the close poll times out); read `error`/`hint`/`ownership` before retrying.
- **Task-ended output loss**: ego can hard-stop the script as a *consequence* of the action and drop buffered output (including the result sentinel), printing `This task space is no longer assigned to the agent: its task has ended … browser commands are paused` and exiting 0. For `close`/`finish`/`complete`/`mark_error`/`handoff`/`wait_control`/`takeover` the tool now re-reads the space list once and decides from that state. Terminal actions may return `{ok:true, …, receipt:null, verifiedBy:"listTaskSpaces", note:"…"}` — **`receipt:null` here is not a failure** (the receipt was dropped; the conclusion comes from the independent read, and `finish` also reports `keep:null` on this path). A gone space means `ownership:"closed"`; a space still listed as `user` counts as success for `finish(keep:true)`/`complete`/`mark_error`. `handoff`/`takeover`/`wait_control` also succeed when the independent read already shows the state they promise (`agentDelegatedToUser`/`agent`/`agent`) — `handedOff`/`tookOver`/`control` + `verifiedBy:"listTaskSpaces"` — instead of failing because the script did not finish; they still fail when the space is gone. **When the space was addressed by `name` and is gone, the recovered result has `spaceId: null`** (the id is only echoed when it was passed in): `spaceId:null` + `verifiedBy:"listTaskSpaces"` is a success, not a missing field. Two exceptions: `finish{keepPages:[...]}` is **not** recovered on this path (page-level outcomes cannot be verified from the space list; the original failure is kept), and `finish(keep:false)` still fails when the space is listed as `user` (it was told to close it). This recovery only runs when that notice is present *and* the outcome was already a failure; normal paths still carry ego's native receipt.
- **No implicit space creation**: only `open` may create a space. Every other space action resolves an existing one by `name`/`id` and fails with `… is currently open. This action only operates on an existing space; it never creates one.` — retrying `close` can no longer create a same-named space and "succeed". **Space actions (including `open`; except `list`/`create`) require `name` or `id` explicitly** — a whitespace-only name such as `"   "` counts as omitted, and since 0.1.12 `delete{}` is rejected host-side too (zero spawns) — and are rejected by the host with `name (string) or id (number) is required for this action` (plus a hint, zero side effects) — a deliberate safety guard against touching the newest space. Only page tools (`ego_app_navigate`/`snapshot`/`click`/`fill`/…) may omit `name` and use the newest agent space (falling back to the newest `agentDelegatedToUser` space).
- **One vocabulary for a vanished space**: absence is reported as `ownership: "closed"` — success for `close`/`finish`/`complete`/`mark_error`, failure for `handoff`/`wait_control`/`takeover`.

## Known ego semantics (handled by the tools)

- `finish({ keep })` takes `"all"` or page labels; validated before calling
- After `handoff`/`takeover` browser commands are paused until `wait_control`; `wait_control`/`takeover` still need the space's `name`/`id` (space actions never default to the newest space)
- `deleteSpaces` removes user-owned spaces only; agent-owned ids hang. After deleting, `delete` polls the list and now **errors** when ids are still listed (or ego reports `skippedRunningSpaceIds`); the result carries `deletedIds`/`stillListed`/`skippedRunningSpaceIds`/`receipt`, and `id`/`scope:"task"` are accepted (`scope:"all"` is explicitly rejected). `force:true` cannot bypass agent-owned targets either: it still returns `ok:false` with `force:true cannot make ego delete…`, unknown ids are named, and a name matching several spaces is rejected in favour of explicit `ids`.
- Spaces in `agentDelegatedToUser` cannot be closed through any API — close them in the ego UI. `close` polls until the entry disappears, so a normal close is no longer reported as a failure; only an explicit refusal (receipt with `error`) or a space still listed after the poll is `ok:false` (with the observed ownership and a hint).
- **An unanswered JavaScript dialog is NOT auto-dismissed between calls.** Measured on ego 0.6.2.5: it blocks every later round on that page (~15 s, `PageEvaluationTimeoutError`). Answer it as soon as a `receipt.dialog` is reported, ideally with `ego_app_dialog{trigger}` in one call.
- Action **receipts** (`popups`, `dialog`) are returned by click/fill/key/pointer/select/upload/download/file_chooser; the key is omitted when the API returned nothing and `{}` when it returned a receipt with nothing to report. `finish` now also exposes ego's receipt under `receipt` (`closedSpace`, `keptManagedLabels`, `closedManagedLabels`, `preservedUnmanagedCount`); `complete`/`mark_error` expose ego's string as `receipt`.
- Downloads must call `saveAs()` inside the same script — `ego_app_download` does it for you.
- ego's default action timeout (~3 s) is not enough for elements far below the viewport. On long pages give `timeoutMs` (**budget >= 15 s**) or scroll the target into view first — 8 s usually still fails. `timeoutMs` is accepted by `click`/`fill`/`navigate`/`wait`/`wait_control` and the file/event tools; for `download`/`file_chooser`/`wait_event` (and the `ego_app_page` equivalents) it is the budget for the whole call: the trigger click gets what is left (>= 500 ms). `wait_control` clamps its `timeoutMs` to `config.timeoutMs - 5000` (upper bound 175 s with the default config; default 165 s when omitted) and reports `requestedTimeoutMs`/`timeoutMs`/`clamped`. `pointer` has no `timeoutMs`; since 0.1.10 `ego_app_page{action:'reload'|'focus'}` forwards it (`close` has none), and explicit `<= 0`/non-finite values are rejected before any side effect.
- A file picker only opens on a user-activated click. Plain CSS and `css=` triggers are pre-scrolled; `@ref` / `loc=` / `xpath=` triggers cannot be, so scroll manually before using them.
- `ego_app_pointer.mouse_click` takes x/y or one plain CSS selector (a leading `css=` is stripped), never a snapshot ref or locator. A CSS target is scrolled into view, clicked, and then the **original viewport position is restored**.
- `css=`, `>> nth=N` and the terminal `:has-text(...)` / `:text-is(...)` / `:text(...)` forms go to ego's own locator parser and are never fed to `document.querySelector`.
- `ego_app_run` plain-text output above `maxOutputBytes` stays `ok:true` + `truncated:true`; the budget counts UTF-8 bytes, not UTF-16 code units.
- **A failed space-list read is not a vanished space**: when `listTaskSpaces()` returns an error object or no `taskSpaces`, `close`/`finish`/`complete`/`mark_error` now **fail** (their error carries `observed ownership: unreadable`, with a hint to run `list`/`ego_app_status` and retry) instead of reporting the space as closed and succeeding; the task-ended probe also gives up on a failed read and keeps the original error. `unreadable` means the state could not be confirmed — neither success nor a completed transition.
- **Hint precedence**: a concrete observation (`task has ended`, `unreadable`, the measured `ownership`) overrides the generic "check the installation / onboarding" hint, so the hint always matches the state actually observed.
